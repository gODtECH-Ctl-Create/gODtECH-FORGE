# FORGE Principles

## 1. Intent before implementation

Understand the problem and desired outcome before deciding what to build.

## 2. Context before decisions

Technical and design decisions should reflect the product, users, constraints, and environment rather than generic defaults.

## 3. Evidence before confidence

When a decision depends on external facts, use appropriate evidence and distinguish verified information from assumptions.

## 4. Scope before scale

A strong product is not the one with the most features. Remove work that does not materially support the outcome.

## 5. Architecture before accumulation

Choose structure and boundaries deliberately before creating large amounts of implementation.

## 6. Experience is part of correctness

A product can be technically functional and still fail because its user experience is poor. User-facing quality therefore belongs in the definition of done.

## 7. Security is continuous

Security is considered during design and implementation, not added as a final checklist.

## 8. Verification is independent of intention

The fact that an agent says something is complete is not evidence that it works.

## 9. Project memory is explicit

Important facts, assumptions, decisions, and state should be recorded so the agent can reason consistently over time.

## 10. Complexity must earn its place

Every rule, dependency, workflow, and abstraction should justify its cost in cognitive load, maintenance, and execution.
