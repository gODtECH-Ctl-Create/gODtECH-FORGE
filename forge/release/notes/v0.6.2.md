# FORGE v0.6.2 — Shared CLI Identity Packaging Fix

FORGE v0.6.2 publishes the shared gODtECH CLI Identity integration with the corrected downstream installation path.

## What changed

- retain the shared FORGE terminal identity introduced in the v0.6.1 release candidate
- pin `@godtech/cli-identity` to the corrected packaging commit
- consume the committed compiled CLI Identity runtime without rebuilding the dependency during normal Git-SHA installation
- preserve banner suppression for JSON, version, MCP server, piped/non-TTY, and explicitly disabled banner modes
- preserve `FORGE_NO_BANNER=1` and `FORGE_ASCII=1`

## Why v0.6.2

The signed `v0.6.1` tag passed FORGE metadata validation, signature verification, ancestry checks, type checking, the complete test suite, and package creation, but the release workflow deliberately stopped before publication when the packed CLI installation exposed a CLI Identity Git-dependency packaging issue.

No v0.6.1 GitHub Release was published. The upstream CLI Identity package was corrected and given a regression smoke test for Git-dependency installation. v0.6.2 is the new immutable release candidate rather than moving or reusing the existing v0.6.1 tag.

## Verified release distribution

The FORGE release pipeline requires a signed annotated tag on a commit already present on `main`, validates aligned release metadata, runs type checking and the complete test suite, installs and executes the packed CLI, verifies SHA-256 checksums, generates Sigstore-backed provenance attestations, and only then publishes the GitHub Release.

Linux and macOS:

```bash
curl -fsSLO https://github.com/gODtECH-Ctl-Create/gODtECH-FORGE/releases/download/v0.6.2/install.sh
sh install.sh 0.6.2
forge --version
```

Windows PowerShell:

```powershell
Invoke-WebRequest https://github.com/gODtECH-Ctl-Create/gODtECH-FORGE/releases/download/v0.6.2/install.ps1 -OutFile install.ps1
.\install.ps1 -Version 0.6.2
forge --version
```
